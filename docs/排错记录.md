# 排错记录

实施过程中真实遇到的四个故障，每个都按照"现象 → 定位 → 根因 → 解决 → 经验"记录。
这四个问题分别落在二层转发、生成树收敛、子接口 ARP、链路聚合协商四处，
说明**只做端到端 ping 不足以定位问题**，必须按层排查。

---

## 问题一：终端拿不到 IP 地址，但 DHCP 配置看起来都对

**现象**
PC1、PC2 的 IPv4 设为 DHCP 后执行 `ipconfig`，长时间停在 `169.254.x.x`；
DHCP 服务器上 `display ip pool` 显示地址池空闲率 100%，完全没有分配记录。

**定位**
先确认中继侧：`LSW3` 上 `display dhcp relay statistics` 可见请求已转发，说明中继没问题。
再回到核心交换机执行 `display vlan`，发现 **LSW2 上只有 40、50、99、100 四个 VLAN，
没有 10、20、30**。

**根因**
`port trunk allow-pass vlan 10 20 30` 只是**允许**这些 VLAN 的报文通过，
并不等于在本机**创建**了这些 VLAN。VLAN 在本机不存在时，报文在入方向即被丢弃，
DHCP 请求根本没走到网关，更到不了服务器。

**解决**
在 LSW2 上补全：

```text
vlan batch 10 20 30 40 50 99 100
```

**经验**
`allow-pass` ≠ `创建`。配置 trunk 前先把全路径上每台交换机的 VLAN 建齐，
这是最容易被忽略、又最费时间排查的低级错误。

## 问题二：网关主备正常，但 PC1 访问服务器时延偏大

**现象**
`display vrrp` 显示 VLAN10 的 Master 在 LSW3，状态正常；但 PC1 ping 服务器
时延明显高于 PC2，链路带宽与配置完全一致。

**定位**
在 LSW1、LSW3、LSW4 上分别执行：

```text
display stp instance 1 brief
```

发现 **VLAN10（实例1）的根桥在 LSW4**，而该 VLAN 的 VRRP Master 在 LSW3。
也就是说流量先上行到 LSW4，再经二层绕回 LSW3 出口，多走了一跳。

**根因**
生成树的阻塞落点与 VRRP 主备关系不对齐。进一步查发现 **LSW2 未配置 MSTP 域参数**，
与其他三台不在同一域，跨域协商退化为单实例计算，阻塞端口落点完全不可控。

**解决**
把 LSW2 纳入同一域并统一实例映射：

```text
stp region-configuration
 region-name HQ
 instance 1 vlan 10 30
 instance 2 vlan 20
 active region-configuration
```

同时在 LSW3 设 `stp instance 1 root primary`、`stp instance 2 root secondary`，
LSW4 反向设置，使**实例根桥 = VRRP Master**。绕行消失，时延恢复正常。

**经验**
二层冗余必须"生成树与网关对齐"。只配 VRRP 不配生成树优先级，
会出现"能用但慢"的隐蔽问题——比不通更难发现。

## 问题三：分支终端能拿到地址，ping 不通网关

**现象**
PC3 通过 AR4 的子接口网关取得 `192.168.110.10/24`，网关显示 `192.168.110.254`，
但 ping 网关全丢包。交换机侧 VLAN 与端口配置均已确认正确。

**定位**
在 AR4 上 `display arp` 看不到 PC3 的 ARP 表项；`display interface Eth-Trunk1.10`
显示接口 Up、无错包。

**根因**
AR4 的三个子接口只配置了 `dot1q termination vid` 与 IP 地址，**未开启 ARP 广播**。
华为路由器子接口默认不发送 ARP 广播报文，因此无法主动学习终端 ARP，
终端发来的 ARP 请求也得不到正常回应。

**解决**
三个子接口下各补一条：

```text
arp broadcast enable
```

**经验**
路由器子接口做网关时，`arp broadcast enable` 是必配项，不是可选项。
这个问题的迷惑性在于"地址、网关、接口状态全都对"，只有 ARP 表是空的。

## 问题四：分支聚合链路始终 down

**现象**
AR4 与 LSW5 之间两条物理链路都已 Up，但 `display eth-trunk 1` 显示成员口状态
为 `Unselect`，Eth-Trunk 整体 Down，分支完全不通。

**定位**
对比两端配置：AR4 侧为

```text
interface Eth-Trunk1
 mode lacp-static
```

而 LSW5 侧只写了 `interface Eth-Trunk1`，**漏了 `mode lacp-static`**，默认为手工模式。

**根因**
LACP 模式需要两端都启用 LACP 协商；一端 LACP、一端手工模式时，
协商报文无人应答，成员口无法转为 Selected。

**解决**
LSW5 侧补 `mode lacp-static`，两端一致后成员口转为 Selected，链路建立。

**经验**
链路聚合"两端模式必须一致"。另外**先建 Eth-Trunk 再加成员口**，
顺序反了容易出现成员口残留配置。

## 小结

| 问题 | 层次 | 关键命令 |
|---|---|---|
| VLAN 未创建 | 二层转发 | `display vlan` |
| MSTP 域不一致 | 生成树收敛 | `display stp instance 1 brief` |
| 子接口缺 ARP 广播 | 三层邻居 | `display arp` |
| 聚合模式不一致 | 链路协商 | `display eth-trunk 1` |

四个问题的现象都表现为"不通"，但根因分散在四个不同层次。
可行的排查顺序是：**物理/接口状态 → 协议状态与表项 → 业务连通性**。

## 问题五：防火墙接口名不是 `GE1/0/x`

**现象**
把 `FW1.txt` 刷到 eNSP 的 USG5500 上，`sysname` 生效了，但从
`interface GigabitEthernet1/0/0` 开始连续报 `Wrong parameter found at '^' position`。

**定位**
在防火墙上执行 `display interface brief`，实际接口是
`GigabitEthernet0/0/0` ～ `GigabitEthernet0/0/8`，共 9 个。

**根因**
不同 eNSP 版本的 USG 镜像接口编号规则不同：有的显示 `GE1/0/x`，
本机这个镜像显示 `GE0/0/x`。而拓扑连线是按"接口序号"绑定的，
序号落在第 0、1 个口上，所以**物理连线没错，只是配置里的名字写错了**。

**解决**
把 `FW1.txt` 中所有 `GigabitEthernet1/0/0` 改为 `0/0/0`、`1/0/1` 改为 `0/0/1`。

**经验**
灌配置前先 `display interface brief` 看一眼真实接口名，比事后逐条改省事得多。

## 问题六：AR2220 不能 `portswitch`，聚合口挂子接口要先转三层

**现象**
按"二层 Eth-Trunk + 子接口"的思路配 AR4，出现一串连锁报错：

```text
Error: The layer-3 interface can not add into a layer-2 trunk.
Error: The layer-2 interface does not support sub-interface.
```

**定位**
1. `portswitch` 在 AR2220 的 GE 口上直接报 `Unrecognized command`——这台设备**不支持把物理口切成二层**；
2. 新建的 `Eth-Trunk1` 默认是二层，所以三层物理口加不进去；
3. 二层聚合口又不允许建子接口，形成死结。

**解决**
新建 Eth-Trunk 后**立刻**把它切成三层，再让物理口加入：

```text
interface Eth-Trunk1
 undo portswitch
 mode lacp-static
quit
interface GigabitEthernet0/0/0
 eth-trunk 1
quit
```

注意顺序：如果先配了 `mode lacp-static`，`undo portswitch` 会报
`Please delete the existing non-default configurations on the interface first`，
必须先删聚合口重建。

**结果**
`display eth-trunk 1` 显示 `Operate status: up`、两成员口 `Selected`；
三个 `Eth-Trunk1.x` 子接口 `up/up`。

## 问题七：USG5500 该镜像不支持源 NAT

**现象**
`nat outbound 2000` 在接口视图报 `Wrong parameter`；`security-policy` 在系统视图也报错。

**定位**
在接口视图输入 `nat ?`，只有 `arp-gratuitous`、`enable` 两项；
系统视图 `nat ?` 只有 `address-group`、`port`、`server`。
也就是说这个镜像**没有 `nat outbound`（源 NAT）**，安全策略也用的是老式
`policy interzone` 而非 `security-policy`。

**解决**
- 目的 NAT（服务器发布）用**不带名字**的写法，已实测通过：
  `nat server 0 protocol tcp global 200.1.1.10 www inside 192.168.40.10 www`
- 源 NAT 无法实现，改为在 ISP 三台路由器上加回程静态路由
  `ip route-static 192.168.0.0 255.255.0.0 <下一跳>`，
  让内网段能被回程路由到，从而在不做地址转换的情况下打通互访。
  该设备默认域间策略为 `permit`，流量可通。

**取舍说明**
这是仿真镜像的能力限制，不是设计错误。真实工程中源 NAT 由防火墙或出口
路由器完成；本仓库保留 NAT Server 的完整配置，源 NAT 以路由替代并在文档中标注。

## 问题八：eNSP 的 `save` 交互因设备而异

**现象**
脚本批量 `save` 时，13 台里只有 3 台被判成功，但多数设备
`display saved-configuration` 里其实已经有配置。

**定位**
逐台打印交互发现两种流程：

- 交换机/路由器：`Are you sure to continue?[Y/N]` → `y` → `Please input the file name(*.cfg,*.zip)[vrpcfg.zip]` → **回车**
- 防火墙：`[Y/N]` → `y` → **再问一次**"是否同步保存到对端设备的启动配置文件？[Y/N]" → 需再答一次

**解决**
用"等提示再回话"代替固定延时：读到 `[Y/N]` 才发 `y`，读到 `file name`/`.zip` 才发回车，
最后等 `successfully` 回显并复查 `display saved-configuration`。

**经验**
自动化刷配置时，凡是带交互确认的命令都不能靠 `sleep` 猜时序。
