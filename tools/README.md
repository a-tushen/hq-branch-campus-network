# 脚本说明

`tools/` 下的脚本用于**生成与校验**拓扑和配置，不是运行网络的必需组件。
它们解决一个实际问题：24 台设备、13 份配置、上百条 IP 容易改一处漏三处，
所以把规划收敛到一个数据源，由脚本统一产出并交叉校验。

## 文件

| 文件 | 说明 |
|---|---|
| `lab_plan.py` | **唯一数据源**。设备清单（名称/型号/坐标/是否终端）、链路（设备+端口）、VLAN 与 IP 规划、ISP 互联、分支规划、NAT 规划、终端静态地址、验证项 |
| `lab_configs.py` | 13 台设备的配置文本，按设备名组织；另含每台设备的"配置要点"注释 |
| `build_lab.py` | 读上面两个模块，生成 `topology/*.topo` 与 `configs/*.txt` |
| `check_lab.py` | 交叉一致性校验，只读，不修改任何文件 |

## 用法

```bash
cd tools
python build_lab.py     # 生成 .topo 与 13 份配置
python check_lab.py     # 校验，全部通过输出 [PASS]
```

依赖：Python 3.8+，标准库即可（`build_lab.py` 只用 `io/os/random/uuid`）。

## check_lab.py 具体校验什么

这是整个工具链里最有价值的部分，它把"人工核对容易漏"的点变成断言：

1. **接口存在性**：24 条链路引用的每个端口序号，都不超过该型号的接口总数
   （避免接到不存在的端口）
2. **VRRP 一致性**：LSW3 与 LSW4 上同一备份组的虚地址必须相同
3. **VRRP ↔ DHCP**：三个地址池的 `gateway-list` 必须等于对应 VLAN 的 VRRP 虚地址
4. **DHCP 中继指向**：中继的 `server-ip` 必须等于 DHCP 服务器接口地址
5. **静态路由下一跳**：LSW2 指向的 `10.99.0.3/0.4/10.0.0.1` 必须真实存在于对应设备
6. **NAT Server 地址**：`inside` 地址必须等于 Server1 的实际地址
7. **子接口 ARP**：AR4 必须包含 `arp broadcast enable`
8. **sysname**：每台设备的设备名与文件名一致

改动地址或 VLAN 后重跑一遍，能在导入 eNSP 之前就把大部分配置错误拦下来。

## 产物可复现性

`build_lab.py` 生成 `.topo` 时使用固定随机种子（20261018），
因此**重复运行得到的设备 UUID 与布局是稳定的**，便于 diff 比较改动。
生成的 `.topo` 为 UTF-8 编码（与 eNSP 1.3.00.100 自身保存的编码一致）。

## 注意

- 拓扑文件由脚本生成，**不要用 eNSP 打开后另存再提交**——eNSP 会重写文件并
  在 `topology/` 下生成 GUID 运行目录，这些目录已在 `.gitignore` 中排除。
- 若手工在 eNSP 里调整了拓扑，记得同步回 `lab_plan.py`，否则下次生成会被覆盖。
